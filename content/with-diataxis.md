Diataxis is a framework of documentation *types*. It identifies four modes of documentation — tutorials, how-to guides, reference, and explanation — and gives each a clear purpose, structure, and tone. It is one of the most influential ideas in modern technical writing, and for good reason: it solves the problem of what shape a document should take.

The Seven-Action model solves a different problem. It describes what a user is trying to *do* when they open the docs. It does not prescribe a content type; it names a need. Appraise, Understand, Explore, Practice, Remember, Develop, Troubleshoot — these are verbs, not templates.

## How they fit together

Diataxis and the Seven-Action model are complementary, not competing. Diataxis gives you the *how*: the structural patterns that make a document clear and effective. The model gives you the *why*: the user need that the document exists to satisfy.

A single Diataxis type can serve multiple actions. A how-to guide might help a user practice a procedure, but it might also help them explore the product for the first time. An explanation might serve understanding, but a well-placed conceptual aside in a troubleshooting guide can anchor a diagnosis in mental models.

Conversely, a single action can be served by multiple Diataxis types. The Practice action might call for a how-to guide for step-by-step procedures, a tutorial for guided learning, and a reference page for the settings the user will configure along the way.

## The sandwich, revisited

The source essay uses a sandwich metaphor: docs frameworks and tools are the bread — essential for holding everything together — but the filling, the thing that gives the sandwich its taste and meaning, is the mental model of user needs. Diataxis is excellent bread. The Seven-Action model is the filling. You need both.

## A practical example

Suppose you are documenting a feature called "Workspaces." Diataxis tells you that you need a how-to guide for creating a workspace, a reference page for workspace settings, and an explanation of the workspace security model. The Seven-Action model asks: which user needs are we covering? The how-to guide serves Practice. The reference page serves Remember. The explanation serves Understand. But are we covering Appraise — does the reader know whether Workspaces is the right feature for their problem? Are we covering Troubleshoot — what happens when a workspace fails to provision?

Diataxis ensures each page is well-formed. The model ensures no user need is left unaddressed.
