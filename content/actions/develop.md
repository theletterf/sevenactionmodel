Users often need to build upon, extend, or integrate with existing products. This is not just about coding — it is about creating additional value on top of the core product. An integration that connects two platforms. An extension that adds a missing feature. A plugin that customizes the experience for a specific workflow. A new application built on an API.

Documentation that serves development is almost always pragmatic. The content type is largely irrelevant — what matters is that the reader can go from idea to working code. Integration guides, approval checklists, style guides, and extension tutorials all serve the same goal: turning the product into a platform.

This kind of documentation acts as a bridge between the product's current capabilities and its potential. It transforms users into co-creators and fosters an ecosystem. When the docs make it easy to build on top of the product, the product grows in ways the original team never anticipated. The metric to watch is not page views — it is the number of integrations and extensions built by people who do not work for you.
